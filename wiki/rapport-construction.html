Rapport de construction : Chevalier IA OS 1.0.0

Construit le 29/09/2026 par Claude (Cowork), à partir de PROMPT-CONSTRUCTION.md et de docs/cahier-des-charges.md (source de vérité).

2. Ce qui a été construit

  1. Coquille OS sans compilation : connexion Google (fenêtre sur ordinateur, redirection sur téléphone et appli installée), contrôle des deux comptes autorisés, menu latéral repliable façon console Firebase, thèmes sombre et clair, routage par ancre, liste des modules.
  2. Module CRM : fiche complète (panneau latéral, plein écran sur téléphone), Kanban animé avec glisser déposer et menu "Déplacer vers…", Liste triable et filtres combinables, recherche sans accents, filtres enregistrés, Réglages.
  3. Accueil : 6 objectifs du mois (5 calculés, 1 manuel avec +1 / +10), sélecteur de mois, À faire (En retard, Aujourd'hui, Sans action prévue) avec "Fait", statistiques, rappel de sauvegarde mensuelle et export CSV.
  4. Charte chevalier-ia.fr : polices et logos du site, Charles jamais redessiné, célébrations (Gagné, Facture payée, objectif atteint, tout est fait), compteurs et barres animés, états vides avec Charles.
  5. PWA sans service worker (manifeste, icônes générées depuis la baguette), détection de nouvelle version, bandeau hors ligne, en têtes de sécurité, robots.txt, action GitHub de déploiement, README.md, version 1.0.0.

3. Décisions prises pendant la construction (docs/decisions-construction.md)

Données

  1. Les champs "date" (datePremierContact, dateProchaineAction, dateInterviewJtbd, dateReveil) sont stockés en texte AAAA-MM-JJ (jour civil, sans fuseau) ; dateRdv en AAAA-MM-JJTHH:MM (heure de Paris) ; les champs "timestamp" en Timestamp Firestore.
  2. dateDernierEchange est renseignée dès la création de la fiche (la création correspond au premier échange).
  3. La création d'une fiche n'ajoute pas de ligne à l'historique (non listée dans les types d'historique du cahier).
  4. "Nouvelle affaire" remet aussi datesEtapes à {premier_contact} (pour que la nouvelle affaire compte à nouveau ses propositions), vide raison de perte, date de réveil et "Rendez vous tenu" ; notes, notes rapides, historique et encaissements sont conservés.
  5. Décocher "Rendez vous tenu" remet dateRdvTenu à vide ; cocher ajoute une ligne "Rendez vous tenu" à l'historique.
  6. Encaissement sans montant sur la fiche : 0 € proposé dans la boîte de dialogue (modifiable).
  7. Identifiant d'une nouvelle offre : dérivé de son nom (atelier_ia), rendu unique si besoin.
  8. Couleurs relevées : corail de Charles #fd6455 (mesuré sur charles-portrait.png), vert Facture payée #3fbf7f, gris lilas Premier contact #b9adc9.

Pipeline, À faire, objectifs

  1. La colonne Facture payée affiche le nombre et le total des factures payées du mois en cours (les cartes payées sont archivées et quittent le Kanban, comme demandé en 4.2).
  2. "Aujourd'hui" contient les actions datées du jour (fiches ni archivées ni perdues) et les fiches Pas maintenant dont la date de réveil est atteinte.
  3. "Fait" sur une ligne "Reprendre contact" (réveil) remet la fiche en Premier contact, puis ouvre le choix de la prochaine action.
  4. La date de réveil est préremplie à +3 mois dans la boîte "Pas maintenant" (modifiable).
  5. Les fiches Interviewé JTBD ne sont pas bloquées en Premier contact : le glisser déposer reste libre, la règle 4.4 décrit l'usage.
  6. "Objectif atteint" : la référence est prise au chargement des données ; la célébration se déclenche quand un objectif du mois en cours passe de moins de 100 % à 100 % ou plus pendant la session.
  7. Les objectifs manuels ajoutés dans Réglages ne se suppriment pas : on les désactive (case "Actif").
  8. La célébration Gagné affiche "Bravo Jérôme !" quel que soit le compte connecté (Charles travaille pour Jérôme).
  9. Les statistiques "Fiches par étape" comptent toutes les fiches, archivées et sorties comprises.

Filtres, Liste, export

  1. Sans le filtre "Archivés", les fiches archivées sont masquées ; avec lui, seules les archivées s'affichent.
  2. "À relancer cette semaine" : semaine du lundi au dimanche, retards inclus, fiches perdues et archivées exclues.
  3. Les filtres (et la recherche) sont partagés entre la Liste et le Kanban pendant la session ; un filtre enregistré se crée depuis la barre de filtres et se renomme ou se supprime dans Réglages.
  4. La liste des villes du filtre est construite à partir des villes saisies sur les fiches.
  5. Export depuis la Liste sans filtre ni recherche : toutes les fiches (archivées comprises), compté comme export complet (dernierExport) ; avec un filtre : les fiches affichées, sans mettre à jour dernierExport. Le bouton Exporter de l'Accueil fait toujours un export complet.
  6. CSV : toutes les colonnes de la section 3.1 plus l'identifiant, libellés en français, nombres avec virgule, dates JJ/MM/AAAA HH:MM (Paris), notes rapides, documents, encaissements et historique sur plusieurs lignes dans leur cellule.
  7. Secteurs et sources : ajout, renommage et retrait dans Réglages ; une valeur retirée reste affichée sur les fiches qui l'utilisent.

Fiche

  1. Les champs de la fiche s'enregistrent à chaque modification ; les Notes s'enregistrent 0,7 s après la frappe et à la sortie du champ.
  2. Le bouton "Email envoyé" est désactivé dans les mêmes cas que "Écrire un email" (pas d'adresse ou opposition).
  3. Suppression définitive : le nom tapé est comparé sans tenir compte des accents ni des majuscules.
  4. Ajout rapide de l'Accueil : prénom et nom, entreprise, source ; la fiche s'ouvre ensuite (pour la note rapide dictée).
  5. "Sans action prévue" propose un bouton "Planifier" (même boîte que la prochaine action).

Coquille, PWA, sécurité

  1. La baguette est marque.svg / marque-inverse.svg du site selon le thème ; le favicon est logo/favicon.svg du site ; les icônes PWA sont générées depuis marque-inverse.svg sur fond sombre avec le halo violet.
  2. Portraits réduits à 512 px de large en PNG optimisé (noms de fichiers inchangés, conformes à la configuration 8.3).
  3. Sur téléphone, le menu s'ouvre toujours élargi par dessus le contenu ; l'état replié ou élargi ne concerne que l'ordinateur.
  4. La connexion par redirection est utilisée sur téléphone, en appli installée, et pour toute fenêtre de moins de 768 px ; si la fenêtre surgissante est bloquée, repli automatique sur la redirection.
  5. Le résultat d'une redirection n'est lu qu'au retour d'une connexion par redirection (évite de charger apis.google.com à chaque ouverture).
  6. Permissions-Policy : caméra, micro, géolocalisation, paiement, USB, capteurs, capture d'écran, lecture auto et MIDI désactivés (la dictée du clavier iPhone n'en a pas besoin).
  7. firebase.json publie la racine du dépôt en ignorant aussi ressources/, PROMPT-CONSTRUCTION.md et firestore.rules.
  8. Kanban : pas de nouveau rendu pendant un glisser déposer (sinon la carte tenue serait détruite par une mise à jour Firestore).

Tests

  1. En mode test uniquement (localhost avec ?emulateurs=1), l'appli expose window.__chevalierTest.connecter(email) qui connecte un compte Google fictif sur l'émulateur Auth ; la vraie fenêtre Google a besoin d'apis.google.com. Le bouton "Se connecter avec Google" est testé à part (fenêtre ou redirection lancée).
  2. Pendant les tests, Playwright sert le SDK Firebase 12.19.0 depuis tests/node_modules/firebase (même version, mêmes fichiers que gstatic) : les tests ne dépendent pas du réseau.
  3. Les appareils de test n'ayant pas d'accès aux serveurs Google, l'émulateur Firestore officiel (cloud-firestore-emulator-v1.22.0.jar, empreinte SHA-256 vérifiée) a été récupéré une fois via le navigateur du Mac ; firebase-tools le télécharge normalement tout seul.
  4. Serveur statique minimal pour les parcours (tests/e2e/serveur.js, port 5050) plutôt que l'émulateur Hosting.
  5. Tests D répartis entre tests/statique.test.js (fichiers) et tests/e2e/controles.spec.js (navigateur) ; parcours C dans tests/e2e/parcours.spec.js.
  6. Émulateurs sur 127.0.0.1, interface web des émulateurs désactivée ; Playwright figé en 1.56.1 (Chromium 141).

4. Actions manuelles restantes (dans l'ordre, sur le Mac)

  1. Pousser le dépôt sur GitHub (je n'avais pas d'accès à GitHub : le dépôt Git complet, avec les branches main et v1, est dans chevalier-ia-os-v1.zip). Dans le Terminal : 
    mkdir -p ~/Projets && cd ~/Projets
unzip "$HOME/Library/CloudStorage/GoogleDrive-jerome.chevalier@gmail.com/Mon Drive/Chevalier-AI/Projets/crm-chevalier-ia/chevalier-ia-os-v1.zip"
cd chevalier-ia-os
git remote add origin https://github.com/jeromechevalier-wq/chevalier-ia-os.git
git push -u origin main
git push -u origin v1

    Le zip est dans le dossier Google Drive crm-chevalier-ia ; on le décompresse hors de Google Drive (dans ~/Projets) pour que le dossier Git ne soit pas synchronisé. Les fichiers de l'appli y sont aussi copiés, en clair, pour les consulter.

  2. Une seule fois : installer Node.js LTS depuis https://nodejs.org, puis : 
    npm install -g firebase-tools
firebase login
cd ~/Projets/chevalier-ia-os

5. Écarts avec le cahier et avec le prompt

  1. Git : la construction a eu lieu dans Cowork, sans identifiants GitHub. La branche v1 a bien été créée à partir de main, avec un commit par étape, mais rien n'a été poussé : le dépôt complet est livré dans le zip (action 1 ci dessus).
  2. Connexion dans les tests : la vraie fenêtre Google a besoin d'apis.google.com, inaccessible depuis l'environnement de test. Les parcours connectent donc un compte fictif sur l'émulateur Auth par window.__chevalierTest (présent uniquement sur localhost avec ?emulateurs=1, jamais en production) ; le bouton "Se connecter avec Google" est testé à part (fenêtre ou redirection bien lancée). La vraie connexion Google est vérifiée par la recette manuelle 13.2.
  3. Émulateur Firestore : l'environnement ne pouvait pas joindre les serveurs Google ; le fichier officiel cloud-firestore-emulator-v1.22.0.jar (empreinte SHA-256 vérifiée) a été téléchargé une fois par le navigateur du Mac, dans Téléchargements. Il reste dans ce dossier avec un dossier emulateur-firestore-morceaux et kit.tgz : tu peux les supprimer. Sur ton Mac, firebase-tools le télécharge tout seul.
  4. Tests D : répartis dans deux fichiers en plus de l'arborescence de la section 10 (tests/statique.test.js, tests/e2e/controles.spec.js), plus un petit serveur de test tests/e2e/serveur.js.
  5. Aucune fonctionnalité hors cahier n'a été ajoutée ; les petits compléments d'ergonomie (bouton "Planifier", date de réveil préremplie, etc.) sont listés dans les décisions.
